## Observations → general problems → choices

The clean baseline is `9605ad0dccea157880a05208babfdac5aa5a5fcd`: 23,353 tracked files, 390,493,640 bytes, 69 product files, 216 files named SKILL.md and 207 named pte.md; 64 product files have equal-byte copies. The review's 450MB figure is approximate; these are the measured tracked bytes. The current views carry weekly evidence limits and obsolete stage narratives. Prior hashes establish byte consistency, not authenticated actions.

1. Without an explicit consequence rule, a worker can satisfy an unlimited number of objectives on trivial changes. Adopt A–E consequence levels, minimum records and independent gates, explicit disagreement/escalation rules, and trigger-only validity for D/E. Merge related fields in one Markdown record where the level allows; full-project adoption must not raise a change's level. Preserve falsifiers before important reliance, authority/evidence distinction and actual failed attempts. The inspiration is the review's DO-178C assurance structure and FDA risk-based assurance analogy; VP is not certification under either. Verify source descriptions before citing them as factual support.
2. History identity, reachability and restoration are different requirements. Require revision control with content-addressed identity, immutable history and a verified independent replica; Git is the ordinary implementation, alternatives must demonstrate equivalence. Keep current source/evidence once, cite historical bytes by commit/path/blob, and prohibit copied source/nested audit packets. External large data lives once per evidence store with hash locators and its recovery replica. This changes the earlier optional-version-control policy under the owner's explicit feedback mandate.
3. Current guidance is a view, not a museum. After tagging and actually restoring the baseline from its independent bundle, remove historical packet/source copies and verbose adoption records from the current tree. Replace adoption history with one short summary, replace retained manifests with current commit/path/hash locators, and rewrite all six views plainly. Original sealed bytes remain unchanged at the tag and replica; new locator manifests are current successor indexes, not rewritten originals presented as historic captures. New facts/rationale do not reconstruct missing historical intent.

Generalise each source observation before implementation. Reject maximum ceremony, cosmetic wording with old mandatory rules, recursion hidden behind exclusion lists, deletion before recovery, and treating a same-host bundle as off-host backup. Scope is VP and its current records, not parallel_gc/honest/NBS. No remote publication. A same-host independent directory is available; owner has been asked for an already authorised off-host destination, which is preferred, not a condition for reversible local progress.

## Plan, predeclared checks and failure conditions

1. Tag the exact baseline as `records-archive-2026-10`; create and verify a self-contained bundle outside the project. Restore into a new external temporary clone, compare every tracked path/mode/OID/byte with baseline, including every path later removed. 2. Amend the standard to 1.1 and align SKILL, playbooks, templates, explanations and examples. 3. Two fresh assessors independently classify the same ten actual historical changes using the draft rules and fixed source material, without each other's answers. Before seeing outcomes require at least 8/10 exact agreements, no more than one non-adjacent disagreement, and both classify the PTE retirement D. Otherwise definitions need revision and a new separately retained trial. Small sample proves only this bounded repeatability, not universal classification reliability.
4. Prune all historical source snapshots and superseded adoption records from the worktree with tracked deletion. Keep one adoption summary and concise current locator manifests for historical evidence owners, plus this migration's records/results. Removed bytes retain baseline commit/path and Git-object identities; actually restored baseline is the recovery evidence. No tracked or untracked current SKILL.md duplicate, no pte.md anywhere in the worktree, no duplicate product bytes except enumerated legitimate exceptions. Ignore rules and workspace ownership must prevent future local restore/check tools from polluting guidance searches.
5. Demonstrate at least three successive constant-shape audit packets using fixed commit/scope/replica locators only. No packet contains any earlier packet or copied source; packet schema/metadata size has no term proportional to prior audits. Check working-tree growth and hashes. Check all active product navigation, obligations/level exemptions, role boundaries, external data locators and new view links.
6. A fresh reader gets only STATE.md (no private context or project access) and must state current stage, all open findings and next action correctly against predeclared authoritative records. Meaning, not literal string overlap, determines pass. If wrong, revise and use a fresh new reader trial. A separate independent Project Audit assesses changed rules, supplied evidence, root/coverage, pruning/custody and advisory closure; it cannot execute repairs or solve the project. Level B acceptance waits for it and the owner-delegated acceptance record.
