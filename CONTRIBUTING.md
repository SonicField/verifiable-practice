# Contributing

Contributions should make Verifiable Practice clearer, more useful, or easier to falsify.

Before proposing a change:

1. State the problem the change addresses.
2. Identify the evidence that the problem exists.
3. Explain what observable result would show that the change did not help.
4. Keep concepts platform-neutral. Put host-specific integration in a separate adapter rather than the canonical skill or playbooks.
5. Update links and routing in `SKILL.md` when adding, removing, or renaming a reference.

Prefer focused changes. Do not add process merely because it sounds rigorous; each requirement should prevent a demonstrated failure or make a material claim easier to check.

## Review Checklist

- The terminal goal is explicit.
- Normative claims have a stated reason or falsifier.
- Examples clarify a non-obvious decision.
- Product-specific terminology has not leaked into canonical material.
- Relative links resolve from the file containing them.
- Negative evidence and limitations are preserved.
